# Codex · Claude 공통 인수인계

## 다른 AI로 넘기거나 동시에 작업할 때

1. 시작할 때 저장소·브랜치·최신 원격 커밋과 미커밋 파일을 확인하고, 해당 작업의 STATUS·DECISIONS·최신 히스토리·열린 PR을 읽는다.
2. **같은 작업을 이어받는 경우:** 이전 AI가 기록과 코드를 함께 커밋·푸시하고 작업 브랜치·PR·남은 일을 남긴다. 다음 AI는 그 브랜치의 최신 커밋을 확인한 뒤 단독으로 이어간다. 미병합 작업을 최신 main에 이미 반영된 것으로 가정하지 않는다.
3. **여러 작업을 동시에 하는 경우:** AI·작업마다 별도 브랜치를 사용한다. 같은 브랜치를 동시에 수정하지 않고, 같은 파일·공통 설정 변경은 순서를 정해 처리한다.
4. 병합 전에는 최신 main과 선행 PR을 확인하고 충돌을 해결한 뒤 필요한 검사를 수행한다. 다른 AI의 변경·미커밋 파일·기존 기록을 reset·강제 푸시로 덮어쓰지 않는다.
5. 종료할 때 변경·사용자 결정·실패/철회·검증·다음 작업을 해당 기록에 남기고 커밋·PR 링크를 적는다. 로컬 저장·원격 푸시·main 병합·배포 상태를 구분한다.

이 절차는 충돌을 줄이는 협업 규칙이다. 자동 잠금이나 충돌 완전 차단 기능을 설치한 것은 아니므로 동일 파일의 동시 편집에는 여전히 충돌이 생길 수 있다.

현재 정리 PR·검증·미완료 상태는 [공통 작업 기록](HISTORY.md), 환경별 연결은 [Cloud 안내](CLOUD.md)를 확인한다.
